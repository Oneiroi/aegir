## Abstract

The Model Context Protocol (MCP) is being rapidly adopted as the integration layer for agentic AI systems — the standard through which LLMs invoke tools, access data, and orchestrate autonomous workflows. It has no security model. Authentication, content inspection, and threat detection are entirely absent from the specification. The industry is deploying MCP at scale and assuming the security is someone else's problem.

We built Aegir to be that problem's solution. In this session we present the first systematic threat model for MCP, mapping the full attack surface against MITRE ATLAS and OWASP LLM Top 10 for Large Language Model Applications. We demonstrate three confirmed attack paths against MCP deployments that bypass existing controls:

**SSRF via Tool Argument URLs** — MCP proxies validate resource URIs at the protocol layer but not the values inside tool call arguments. An attacker passes an AWS IMDS URL (`http://169.254.169.254/latest/meta-data/`) as a tool parameter; the proxy forwards it without inspection, reaching internal services the model was never meant to access.

**DNS Rebinding Bypass** — URI validation occurs at parse time. An attacker-controlled hostname passes the blocklist check, then resolves to `192.168.1.1` at TCP connection time. Standard blocklist enforcement is bypassed entirely.

**Indirect Prompt Injection via Tool Results** — Content returned by upstream tool calls flows back into model context without sanitisation. Malicious instructions embedded in a database response, fetched document, or API reply execute with full system prompt authority.

We also present the finding the industry needs to hear: pattern-based detection at the transport layer has a hard ceiling of approximately 62% MITRE ATLAS coverage. The remaining 38% — Crescendo attacks (AML.T0054.007), distributed model extraction, and RAG poisoning — cannot be caught by a proxy that lacks semantic understanding of what the model is being asked to do.

We release Aegir, a production-grade open-source MCP security gateway, including the full ATLAS gap analysis document that tells operators exactly what Aegir protects against — and what it does not. Because a security tool that is honest about its limits is more useful than one that isn't.
